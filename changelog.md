## 3.0.0 - 2026-04-03
* The SDK now includes structured HTTP request/response logging. Pass a `LogConfig` or `Logger` instance via the new `logging_config` parameter on `HttpClient` and `AsyncHttpClient` to enable debug-level request tracing and error-level failure logging; sensitive headers (e.g. `Authorization`, `x-api-key`, cookies) are automatically redacted.
* `BaseHttpResponse` now exposes a `status_code` property for direct access to the HTTP response status code.
* `AppointmentPscLabs` has been expanded from a `typing.Literal["quest"]` to a full `StrEnum` with `QUEST` and `SONORA_QUEST` values. Code that previously compared against the string literal `"quest"` will need to be updated to use `AppointmentPscLabs.QUEST`.
* The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`, and the five `LinkBulk*RequestTeamId` types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed from `vital.link`.
* The `parser_create_job` method on `LabReportClient` and `AsyncLabReportClient` now accepts a list of files (`typing.List[core.File]`) instead of a single file, enabling multi-file lab report parsing jobs. Callers must wrap their existing `file` argument in a list: `file=[my_file]`.
* Five previously exported `Link*` types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed from the public API and should be dropped from any import statements.
* The SDK also adds three new submodule namespaces (`compendium`, `lab_account`, `order_transaction`) and over 40 new public types including `CanonicalCandidate`, `ClientFacingLabAccount`, `OrderSummary`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more.
* The `get_psc_appointment_availability` method (both sync and async) now requires a new `lab` parameter of type `AppointmentPscLabs`. Existing callers that do not pass this argument will receive a `TypeError` at runtime and must be updated to supply the desired lab (e.g., `lab=AppointmentPscLabs.QUEST`).
* In addition, several methods gained new optional parameters: `lab_account_id` and `lab_slug` on `create_lab_test`/`update_lab_test`, `lab_slug` on `get_markers`, `order_transaction_id` on `get_orders`, `appointment_notes` on `request_phlebotomy_appointment`, `idempotency_key`/`idempotency_error` on `book_psc_appointment`, and `clinical_notes` on `create_order`.
* The SDK now supports additional filtering and configuration options across the lab tests API. New optional parameters include `lab_slug` and `lab_account_id` for lab test creation, `lab_slug` for marker filtering, `order_transaction_id` for order listing, `appointment_notes` for PSC appointment booking, `clinical_notes` for order creation, and `idempotency_key`/`idempotency_error` headers for idempotent PSC appointment booking (closed beta). The `get_psc_appointment_availability` method now accepts a required `lab` parameter (type `AppointmentPscLabs`) instead of a hardcoded lab value, and an optional `allow_stale` parameter to permit cached availability data.
* The `team_id` parameter has been removed from the `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause` methods on `LinkClient` and `AsyncLinkClient`. The associated enum types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed — update any imports and remove `team_id` keyword arguments from affected calls. The `connect_manual_provider` method now accepts three new optional parameters: `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`.
* The `address` parameter in `client.user.create_user_info()` (and its async equivalent) has been renamed from `Address` to `UserAddress`. Callers must import and pass a `UserAddress` instance instead of `Address`.
* The `job_id` field has been removed from the `ParsingJob` model; a new optional `failure_reason` field (of type `ParsingJobFailureReason`) has been added in its place.
* The `content` field on `Jpeg` and `Png` models has changed from `str` to `bytes`, reflecting the actual binary nature of image data.
* New sub-clients are now available: `client.compendium` (lab test search and conversion), `client.lab_account`, and `client.order_transaction`. Additional optional fields have been added to `ClientFacingOrder`, `ClientFacingInsulinInjectionSample`, and `ResultMetadata`. An optional `logging` parameter is now supported on `Vital` and `AsyncVital` constructors.
* The SDK now includes three new API clients: `LabAccountClient` (for retrieving team lab accounts), `OrderTransactionClient` (for fetching order transactions, raw results, and PDF downloads), and raw compendium clients exposing `search` and `convert` endpoints. A new logging subsystem (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is now available from `vital.core` for configurable SDK-level logging.
* The SDK now includes a new `RawOrderTransactionClient` (and its async counterpart) for retrieving order transaction details, raw lab results, and streamed PDF reports via the `v3/order_transaction/` endpoints. Dozens of new types are now exported from `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingOrderInTransaction`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `OrderSummary`, `ClientFacingLabAccount`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new expression types and enums (`InsulinInjectionTimeseriesExpr`, `ClientFacingInsulinInjectionSampleBolusPurpose`, `ClientFacingInsulinInjectionSampleDeliveryForm`, `ClientFacingInsulinInjectionSampleDeliveryMode`). Derived readiness metrics are now available via `DerivedReadinessColumnExpr` and a new `recovery_readiness_score` field on `ClientFacingSleep`. Additional additions include Sonora Quest lab support (`SONORA_QUEST` in `AppointmentProvider`, `ClientFacingLabs`, and `CompendiumSearchLabs`), order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab account types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), lab report parsing job webhook event types, and new optional fields for appointment booking/rescheduling (`appointment_notes`, `async_confirmation`, confirmation timeout controls).
* The SDK now includes several new types and expanded enum values to support richer lab testing and order management workflows. New enums include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`. New models include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`. Existing enums (`Labs`, `Providers`, `ManualProviders`, `PasswordProviders`, `OrderLowLevelStatus`, `OrderStatus`, `PayorCodeExternalProvider`) have been extended with new values, and `PatientAddress` variants now support an optional `access_notes` field.
* The SDK now includes several new types to support lab compendium search (`SearchCompendiumResponse`, `SearchMode`), a comprehensive `UsState` enum, a new `UserAddress` model, and a `ResultMetadataGender` enum. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains a new `RECOVERY_READINESS_SCORE` enum value.
