## 3.0.0 - 2026-04-02
* Several breaking changes have been made in this release:
* The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`. Callers using `visit()` with an `insulin_injection` callback or referencing `IntervalTimeseriesExprTimeseries.INSULIN_INJECTION` must update their code.
* The types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from `vital.link`. Any imports of these types must be removed.
* `AppointmentPscLabs` has changed from `typing.Literal["quest"]` to a `StrEnum` class; code treating it as a plain string literal type may need to be updated.
* New additions include HTTP request/response logging (with sensitive header redaction) via an optional `logging_config` parameter on the HTTP client, a `status_code` property on `BaseHttpResponse`, and `SONORA_QUEST` as a new value in `AppointmentPscLabs`.
* The `parser_create_job` method on `LabReportClient` and `AsyncLabReportClient` now accepts `file: List[core.File]` instead of `file: core.File`, enabling multi-file lab report parsing jobs — existing callers must wrap their single file in a list (e.g. `file=[my_file]`). The `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` types have been removed from the public API. New sub-modules (`compendium`, `lab_account`, `order_transaction`) and approximately 50 new model types (including `OrderSummary`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `LabAccountStatus`, `UsState`, `UserAddress`, `ParsingJobFailureReason`, and more) are now available. Client wrappers also support an optional `logging` parameter for request/response logging.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` (e.g., `AppointmentPscLabs.QUEST`). Existing callers that omit this argument will receive a `TypeError` and must be updated to pass the required `lab` value.
* The SDK also adds several new optional parameters across lab test methods: `lab_account_id` and `lab_slug` on `create_lab_test`, `lab_slug` on `get_markers`, `order_transaction_id` on order listing, `appointment_notes` on `request_phlebotomy_appointment`, `allow_stale` and idempotency support (`idempotency_key`, `idempotency_error`) on `book_psc_appointment`, and `clinical_notes` on `create_order`.
* The SDK now exposes several new optional parameters across the lab tests client. Notable additions include `lab_slug` for filtering markers, `order_transaction_id` for order listing, `appointment_notes` for PSC appointment scheduling, `clinical_notes` for order creation, and `idempotency_key`/`idempotency_error` support (closed beta) for PSC appointment booking. The `get_psc_appointment_availability` method now accepts a `lab` parameter (of type `AppointmentPscLabs`) instead of a hardcoded lab value, and a new `allow_stale` flag to permit cached availability results. Two new types, `AppointmentPscLabs` and `Labs`, are also now available.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. The associated enum types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have also been removed. Callers passing `team_id` as a keyword argument to any of these methods must remove it. Additionally, `connect_manual_provider` now accepts new optional parameters `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`.
* The `address` parameter in `UserClient.create_user()` and `AsyncUserClient.create_user()` (and their raw counterparts) has changed from `Address` to `UserAddress`. Update all call sites to import and use `UserAddress` instead of `Address`.
* Additionally, several new capabilities are available: `Vital` and `AsyncVital` now expose `compendium`, `lab_account`, and `order_transaction` client properties, and both clients accept a new optional `logging` parameter for configurable SDK-level logging. `ClientFacingOrder` gains `last_event`, `clinical_notes`, `origin`, and `order_transaction` fields; `ClientFacingInsulinInjectionSample` gains `delivery_mode`, `delivery_form`, and `bolus_purpose` fields.
* Note: `Jpeg.content` and `Png.content` have changed type from `str` to `bytes`, and `ParsingJob.job_id` has been removed — update any code that accesses these fields.
* The SDK now includes three new client modules. `LabAccountClient` (and its async variant) provides a `get_team_lab_accounts()` method for retrieving team lab account information. `OrderTransactionClient` (and its async variant) exposes `get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()` for working with order transactions. The `compendium` module gains raw client support for `search()` and `convert()` operations. A structured logging system (`ILogger`, `ConsoleLogger`, `Logger`, `LogConfig`, `create_logger`) is also now available via `vital.core`.
* The SDK now includes a new `RawOrderTransactionClient` (sync and async) for interacting with the `v3/order_transaction` API, supporting retrieval of transaction details, raw lab results, and streaming PDF results. Over 40 new public types have been added to `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `SearchCompendiumResponse`, and many more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data, derived readiness column expressions, and awakenings value macro expressions. New types for order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab account management (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), and lab report parsing job events have been added. New enum values include `SONORA_QUEST` for lab and appointment provider enums, `INSULIN_PUMP` for device source type enums, and `DERIVED_READINESS` for index column expressions. Several existing models have received new optional fields, including async confirmation controls on `AppointmentBookingRequest`, `recovery_readiness_score` on `ClientFacingSleep`, and `status_detail` on `ClientFacingOrderEvent`.
* The SDK now includes several new enums and model types to support expanded lab testing and order lifecycle workflows. New enums include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`. New models include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`. Additional enum values have been added to `Labs` (`SONORA_QUEST`, `CRL`), `Providers`/`ManualProviders`/`PasswordProviders` (`TANDEM_SOURCE`, `SAMSUNG_HEALTH`), `OrderStatus` (corrected result states and `LAB_PROCESSING_BLOCKED`), `OrderLowLevelStatus` (`CORRECTED`, `LAB_PROCESSING_BLOCKED`), and `PayorCodeExternalProvider` (`APERO`, `PVERIFY`). Patient address models now include an optional `access_notes` field, and `LabResultsRaw` includes an optional `order_transaction` field.
* The SDK now includes several new types: `ResultMetadataGender`, `SearchMode`, `SearchCompendiumResponse`, `UsState`, and `UserAddress`. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains a new `RECOVERY_READINESS_SCORE` enum value.
