## 3.0.0 - 2026-04-02
* Several breaking changes are included in this release:
* **`AppointmentPscLabs` type change**: `AppointmentPscLabs` was previously a `Literal["quest"]` type alias and is now a `StrEnum` class. Code that assigns or compares against the string `"quest"` directly (e.g. `== "quest"`) may need to be updated to use `AppointmentPscLabs.QUEST`. A new `SONORA_QUEST` value has also been added.
* **`IntervalTimeseriesExprTimeseries.INSULIN_INJECTION` removed**: The `INSULIN_INJECTION` enum member and its corresponding `visit()` callback have been removed. Update any `visit()` calls or enum comparisons that reference `insulin_injection`.
* **`vital.link` bulk operation team ID types removed**: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from `vital.link`.
* New in this release: HTTP clients now support optional structured logging via a `logging_config` parameter, and `BaseHttpResponse` exposes a new `status_code` property.
* Several breaking changes are included in this release:
* 1. **`parser_create_job` signature change**: The `file` parameter on `LabReportClient.parser_create_job()` (and its async counterpart) has changed from `core.File` to `typing.List[core.File]`. Update all call sites to wrap single files in a list: `file=[my_file]`.
* 2. **Removed exported types**: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from the public API.
* New capabilities include three new submodules (`compendium`, `lab_account`, `order_transaction`) and over 40 new types such as `CanonicalCandidate`, `ClientFacingLabAccount`, `OrderSummary`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more. An optional `logging` parameter has also been added to client wrappers.
* The `get_psc_appointment_availability` method on `LabTestsClient` and `AsyncLabTestsClient` now requires a `lab` parameter of type `AppointmentPscLabs` (e.g., `AppointmentPscLabs.QUEST`). Existing callers that do not pass this parameter will receive a `TypeError`. Several other methods have also been expanded with new optional parameters: `create_lab_test` gains `lab_account_id` and `lab_slug`; `get_markers` gains `lab_slug`; `get_orders` gains `order_transaction_id`; `request_phlebotomy_appointment` gains `appointment_notes`; `book_psc_appointment` gains `idempotency_key` and `idempotency_error`; and `create_order` gains `clinical_notes`.
* The SDK now supports several new optional parameters across the lab tests and orders API:
* `lab_account_id` and `lab_slug` on lab test creation and marker listing methods for finer lab targeting
* `order_transaction_id` filter on order listing
* `appointment_notes` on PSC appointment creation
* `clinical_notes` on order creation
* `lab` (required, `AppointmentPscLabs` type) and `allow_stale` on `get_psc_appointment_availability`, replacing the previously hardcoded `"quest"` lab value — **callers must now pass the `lab` argument explicitly**
* `idempotency_key` and `idempotency_error` on PSC appointment booking for closed-beta idempotency support
* New types `AppointmentPscLabs` and `Labs` are also available.
* The `team_id` parameter has been removed from `link.list_bulk_ops()`, `link.bulk_import()`, `link.bulk_trigger_historical_pull()`, `link.bulk_export()`, and `link.bulk_pause()`. Callers passing `team_id` by keyword argument will receive a `TypeError`. The five associated enum types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have also been removed — remove any imports and usages of these types from your code. As a new addition, `link.connect_manual_provider()` now accepts optional `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` parameters.
* The `address` parameter type in `client.user.create_user()` (and its async/raw variants) has changed from `Address` to `UserAddress`. Callers must update their imports and replace `Address(...)` with `UserAddress(...)`.
* Additionally, the `job_id` field has been removed from `ParsingJob`, `Jpeg.content` and `Png.content` now return `bytes` instead of `str`, and several `ResultMetadata` fields (`patient_first_name`, `patient_last_name`, `dob`, `lab_name`) are now optional.
* New capabilities include three new client namespaces (`client.compendium`, `client.lab_account`, `client.order_transaction`), optional SDK logging configuration via the `logging` parameter on the `Vital`/`AsyncVital` constructors, new fields on `ClientFacingOrder` (`clinical_notes`, `last_event`, `origin`, `order_transaction`) and `ClientFacingInsulinInjectionSample` (`delivery_mode`, `delivery_form`, `bolus_purpose`).
* The SDK now includes three new client namespaces for lab testing workflows:
* **`lab_account`** — retrieve team lab accounts filtered by ID or status via `get_team_lab_accounts()`.
* **`order_transaction`** — fetch order transactions, their results, and result PDFs via `get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()`.
* **`compendium`** — search and convert compendium entries via `search()` and `convert()` (raw response variants also available).
* A new structured logging system (`ILogger`, `ConsoleLogger`, `Logger`, `LogConfig`, `LogLevel`, `create_logger`) is also now available from `vital.core`.
* The SDK now includes a new `RawOrderTransactionClient` (and async variant) with methods to retrieve order transactions, their lab results, and stream result PDFs via the `v3/order_transaction` endpoints. Approximately 40 new public types have been added to `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `ProviderIdConversionResponse`, and many more. The `Address` model now supports an optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new types for bolus purpose, delivery form, and delivery mode. New types for derived readiness columns, awakenings macro expressions, lab accounts, order transactions, and lab report parsing job webhook events have been added. Sonora Quest is now available as an appointment provider and lab option across relevant enums, and `INSULIN_PUMP` has been added as a device source type. The `ClientFacingSleep` model now includes a `recovery_readiness_score` field, and appointment booking/reschedule requests support new optional async confirmation and notes fields.
* The SDK now includes several new types and expanded enumerations. New enums added include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`. New models include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`. Existing enums have been extended with new members: `Labs` gains `SONORA_QUEST` and `CRL`; `Providers` and `ManualProviders` gain `SAMSUNG_HEALTH` and `TANDEM_SOURCE`; `OrderLowLevelStatus` gains `CORRECTED` and `LAB_PROCESSING_BLOCKED`; `OrderStatus` gains corrected and lab-processing-blocked variants; `PayorCodeExternalProvider` gains `APERO` and `PVERIFY`. Patient address models now include an optional `access_notes` field, and `LabResultsRaw` includes a new optional `order_transaction` field.
* The SDK now includes several new types and model enhancements:
* New `ResultMetadataGender`, `SearchMode`, and `UsState` enums with forward-compatible unknown-value handling.
* New `SearchCompendiumResponse` and `UserAddress` Pydantic models for lab compendium search and address data.
* `UsAddress` now supports an optional `access_notes` field.
* `SleepColumnExprSleep` enum gains the `RECOVERY_READINESS_SCORE` value.
