## 3.0.0 - 2026-04-08
* Several breaking changes are included in this release:
* The `AppointmentPscLabs` type has changed from `typing.Literal["quest"]` to a `StrEnum` class. Code that used the type annotation directly (e.g. `AppointmentPscLabs = "quest"`) must be updated to use `AppointmentPscLabs.QUEST`. A new `SONORA_QUEST` value is also available.
* The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`. Any `.visit()` calls that passed an `insulin_injection` callback must remove that argument.
* The public types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from `vital.link`.
* New in this release: HTTP clients now support optional structured logging (configurable via `LogConfig` or a custom `Logger`) with automatic redaction of sensitive headers. `BaseHttpResponse` now exposes a `status_code` property.
* The `parser_create_job` method on `LabReportClient` (and its async counterpart) now accepts `typing.List[core.File]` instead of a single `core.File` for the `file` parameter, enabling multi-file lab report parsing. Existing callers must wrap their single file in a list: `file=[my_file]`.
* The following previously exported names have been removed: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`.
* Numerous new types and submodules have been added, including `compendium`, `lab_account`, `order_transaction`, `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more. An optional `logging` configuration parameter is now available on the client wrappers.
* The `get_psc_appointment_availability()` method on `LabTestsClient` and `AsyncLabTestsClient` now requires a new `lab` parameter of type `AppointmentPscLabs` (e.g. `AppointmentPscLabs.QUEST`). Existing callers that omit this argument will receive a `TypeError` at runtime and must be updated to pass the `lab` argument.
* Additionally, several methods gain new optional parameters: `lab_account_id` and `lab_slug` on lab test create/update methods, `lab_slug` on `get_markers()`, `order_transaction_id` on order listing, `appointment_notes` on `request_phlebotomy_appointment()`, `idempotency_key` and `idempotency_error` on `book_psc_appointment()`, and `clinical_notes` on `create_order()`.
* The SDK now supports additional filtering and configuration options across the lab tests and appointments APIs. New optional parameters include `lab_slug` and `lab_account_id` for lab test creation and marker lookup, `order_transaction_id` for order filtering, `appointment_notes` for PSC appointment scheduling, `clinical_notes` for order creation, and `idempotency_key`/`idempotency_error` for idempotent PSC appointment booking. The `get_psc_appointment_availability` method now accepts a required `lab` parameter (of new type `AppointmentPscLabs`) and an optional `allow_stale` flag, replacing the previously hardcoded lab value.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. Callers passing `team_id` as a keyword argument must remove it to avoid a `TypeError`. Additionally, `connect_manual_provider` now accepts new optional parameters `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` for richer SDK metadata and permission reporting.
* Several breaking changes are included in this release:
* **`UserClient.create_user` / `UserInfo.address`**: The `address` parameter type has changed from `Address` to `UserAddress`. Update all call sites to import and construct `UserAddress` instead of `Address`.
* **`ParsingJob`**: The required field `job_id` has been removed. Code that reads `parsing_job.job_id` will raise an `AttributeError`. A new optional `failure_reason` field has been added.
* **`Jpeg.content` / `Png.content`**: The `content` field type has changed from `str` to `bytes`. Any code that treats image content as a string will need to be updated.
* New capabilities also included in this release:
* Three new top-level clients are now available: `client.compendium` (lab test search and conversion), `client.lab_account`, and `client.order_transaction`.
* A new optional `logging` parameter on `Vital` and `AsyncVital` constructors allows configuring SDK-level logging via a `LogConfig` dict or a `Logger` instance.
* `ClientFacingOrder` gains new fields: `clinical_notes`, `last_event` (the preferred replacement for the now-deprecated `status`), `origin`, and `order_transaction`.
* `ClientFacingInsulinInjectionSample` gains new optional fields: `delivery_mode`, `delivery_form`, and `bolus_purpose`.
* The SDK now includes two new client namespaces: `lab_account` (providing `get_team_lab_accounts()`) and `order_transaction` (providing `get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()`). Raw HTTP response variants for the compendium `search` and `convert` endpoints are also available via `client.compendium.with_raw_response`. Additionally, a structured logging framework (`ILogger`, `ConsoleLogger`, `Logger`, `LogConfig`, `LogLevel`, `create_logger`) is now exported from `vital.core` for advanced logging configuration.
* The SDK now exposes a new `order_transaction` client (sync and async) with methods to retrieve order transactions (`get_transaction`), fetch raw lab results (`get_transaction_result`), and stream result PDFs (`get_transaction_result_pdf`). Approximately 40 new public types have been added to `vital.types`, including `ClientFacingOrderTransaction`, `OrderTransactionStatus`, `ClientFacingLabAccount`, `SearchCompendiumResponse`, `UserAddress`, `UsState`, and more. The `Address` model now includes an optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new `InsulinInjectionTimeseriesExpr` expression type and related delivery mode/form/purpose enums. New derived readiness column expressions (`DerivedReadinessColumnExpr`) and an `AwakeningsValueMacroExpr` have been added to the aggregate expression system. Sonora Quest is now available as a lab and appointment provider (`SONORA_QUEST` across `AppointmentProvider`, `ClientFacingLabs`, and the new `CompendiumSearchLabs` enum). New models for order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), lab account management (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), and lab report parsing job events are now available. `AppointmentBookingRequest` gains optional async-confirmation fields and notes; `ClientFacingSleep` gains a `recovery_readiness_score` field.
* The SDK now supports new labs (`SONORA_QUEST`, `CRL`), providers (`TANDEM_SOURCE`, `SAMSUNG_HEALTH`), and payor code providers (`APERO`, `PVERIFY`). New enums have been added for `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, `LabAccountDelegatedFlow`, `LabAccountStatus`, and `ParsingJobFailureReason`. Additional models `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate` are now available. `PatientAddress` variants now include an optional `access_notes` field, and `LabResultsRaw` includes an optional `order_transaction` field.
* The SDK now includes several new types: `SearchCompendiumResponse` and `SearchMode` for lab compendium search, `UsState` for US state codes, `UserAddress` for structured address data, and `ResultMetadataGender` for gender classification. The `SleepColumnExprSleep` enum gains a new `RECOVERY_READINESS_SCORE` value, and `UsAddress` gains an optional `access_notes` field.
