## 3.0.0 - 2026-04-09
* The SDK now supports optional structured HTTP request/response logging via a new `logging_config` parameter on the HTTP client, with automatic redaction of sensitive headers. A new `status_code` property has been added to `BaseHttpResponse` for direct access to the HTTP status code. `AppointmentPscLabs` has been expanded to include the new `SONORA_QUEST` value alongside `QUEST`. Note: the `INSULIN_INJECTION` value has been removed from `IntervalTimeseriesExprTimeseries`, and the `LinkBulk*RequestTeamId` types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed from `vital.link`.
* The `parser_create_job` method on `LabReportClient` and `AsyncLabReportClient` now accepts `typing.List[core.File]` instead of a single `core.File` for the `file` parameter, enabling multi-file lab report parsing jobs — existing callers passing a single file must wrap it in a list.
* Several `Link*` request types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed from the public SDK namespace.
* The SDK also introduces new types and sub-modules including `compendium`, `lab_account`, `order_transaction`, `OrderSummary`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and many more.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` (e.g. `AppointmentPscLabs.QUEST`). Existing callers that omit this argument will receive a `TypeError` at runtime and must be updated to pass the new required parameter.
* Additionally, several new optional parameters have been added across lab test methods: `lab_slug` and `lab_account_id` on lab test creation, `lab_slug` on `get_markers`, `order_transaction_id` on order listing, `appointment_notes` on `request_phlebotomy_appointment`, `allow_stale` and `idempotency_key`/`idempotency_error` on PSC appointment methods, and `clinical_notes` on `create_order`. Two new types, `AppointmentPscLabs` and `Labs`, are now available for import.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` (previously the lab was hardcoded to `"quest"`). Callers must update their code to pass this argument explicitly.
* Additionally, several new optional parameters have been added across lab test and appointment endpoints: `lab_slug` and `lab_account_id` on lab test create/update, `lab_slug` on get markers, `order_transaction_id` on list orders, `appointment_notes` on create appointment, `clinical_notes` on create order, and `idempotency_key`/`idempotency_error` on book PSC appointment.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. Callers passing `team_id` to any of these methods must remove that argument. The associated enum types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have also been removed from the package.
* `connect_manual_provider` now accepts three new optional parameters — `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` — allowing callers to report SDK version information and specify granted permissions when connecting a manual provider.
* The `address` parameter of the `create_user` method (on both `UserClient` and `AsyncUserClient`) now requires a `UserAddress` object instead of the previous `Address` type. Update any existing calls to import and use `UserAddress` from `vital` in place of `Address`.
* Several other breaking changes are also included: `Jpeg.content` and `Png.content` have changed type from `str` to `bytes`; the `job_id` field has been removed from `ParsingJob`; and several `bool` fields have been narrowed to `Literal[True]` or `Literal[False]` (affecting `Placeholder`, `HistoricalPullCompleted`, `UserRefreshSuccessResponse`, `UserRefreshErrorResponse`, and `ClientFacingProfile.wheelchair_use`).
* New capabilities include three new clients (`compendium`, `lab_account`, `order_transaction`) on `Vital`/`AsyncVital`, an optional `logging` parameter for SDK-wide log configuration, and new optional fields across `ClientFacingOrder`, `ClientFacingInsulinInjectionSample`, `ResultMetadata`, and `ParsingJob`.
* The SDK now exposes three new client namespaces: `lab_account` (for retrieving team lab accounts), `order_transaction` (for fetching transaction details, results, and result PDFs), and an expanded `compendium` raw client (for `search` and `convert` operations). A new structured logging system (`ILogger`, `ConsoleLogger`, `Logger`, `LogConfig`, `LogLevel`, `create_logger`) is also available via `vital.core`. Additionally, optional fields marked as `OMIT` are now correctly excluded from serialized request payloads.
* The SDK now includes a new `RawOrderTransactionClient` (and async variant) for fetching order transactions, their lab results, and streaming result PDFs via the `v3/order_transaction` API. Over 40 new public types have been added, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `UserAddress`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data, derived readiness metrics, and lab account management. New types include `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `ConvertCompendiumResponse`, `CanonicalCandidate`, and lab report parsing job event models. Existing models such as `AppointmentBookingRequest`, `ClientFacingAppointment`, and `ClientFacingSleep` have been extended with new optional fields, and `SONORA_QUEST` has been added as a supported appointment provider and lab.
* The SDK now includes several new types and enum values to support expanded lab testing and health data workflows. New model classes include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, `ParsingJobFailureReason`, `PerLabCandidate`, `ProviderIdConversionResponse`, `RelatedCandidate`, and `OrderSummary`. New enum members have been added to `Labs` (Sonora Quest, CRL), `Providers` and `ManualProviders` (Samsung Health), `PasswordProviders` (Tandem Source), `OrderLowLevelStatus` and `OrderStatus` (corrected and lab-processing-blocked statuses), and `PayorCodeExternalProvider` (Apero, Pverify). The `PatientAddress`, `PatientAddressCompatible`, and `PatientAddressWithValidation` models now include an optional `access_notes` field, and `LabResultsRaw` includes an optional `order_transaction` field.
* The SDK now includes several new types: `ResultMetadataGender`, `SearchMode`, and `SearchCompendiumResponse` to support lab compendium search functionality; a `UsState` enum covering all 50 US states; and a new `UserAddress` model. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains a new `RECOVERY_READINESS_SCORE` enum value.
