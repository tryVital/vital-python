## 3.0.0 - 2026-04-02
* Several breaking changes are included in this release:
* The `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` types have been removed from `vital.link`. Remove any imports or usages of these classes.
* The `INSULIN_INJECTION` member has been removed from the `IntervalTimeseriesExprTimeseries` enum; update any `.visit()` calls to remove the `insulin_injection` callback argument.
* `AppointmentPscLabs` has changed from a `typing.Literal["quest"]` type alias to a `StrEnum` with `QUEST` and `SONORA_QUEST` values; direct string comparisons should be updated accordingly.
* New additions in this release: the `BaseHttpResponse` now exposes a `status_code` property, HTTP requests now emit structured debug/error log messages (with sensitive headers automatically redacted), and `AppointmentPscLabs` gains a new `SONORA_QUEST` value.
* **Breaking changes in this release:**
* The `file` parameter of `parser_create_job` (available on both `LabReportClient` and `AsyncLabReportClient`, as well as their raw counterparts) has changed from a single `core.File` to `typing.List[core.File]`. Existing callers must wrap their file in a list: `file=[my_file]`.
* The following type aliases have been removed from the top-level `vital` namespace: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`.
**New capabilities:**
* Three new submodules are now available: `vital.compendium`, `vital.lab_account`, and `vital.order_transaction`.
* Over 40 new public types have been added, including `CanonicalCandidate`, `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderOrigin`, `OrderSummary`, `OrderStatusDetail`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more.
* The client wrapper now accepts an optional `logging` parameter (`LogConfig | Logger`) for configurable request/response logging.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` to specify which lab to check for availability. Existing callers must be updated to pass this new required argument (e.g., `lab=AppointmentPscLabs.QUEST`). Several methods also gain new optional parameters: `lab_slug` and `lab_account_id` on lab test methods, `order_transaction_id` for order filtering, `appointment_notes` for phlebotomy appointments, `clinical_notes` for order creation, and `idempotency_key`/`idempotency_error` for PSC appointment booking.
* The `get_psc_appointment_availability` method on `LabTestsClient` now requires a `lab` parameter of type `AppointmentPscLabs` (previously the lab was hardcoded to `"quest"`). Existing callers must be updated to pass the desired lab explicitly.
* Additional optional parameters have been added across several lab test and appointment methods: `lab_slug` and `lab_account_id` on create/update lab test, `lab_slug` on `get_markers`, `order_transaction_id` on `get_orders`, `clinical_notes` on `create_unconfirmed_order`, `appointment_notes` on book appointment, and `idempotency_key`/`idempotency_error` on `book_psc_appointment`.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause` (both sync and async variants). Callers using `team_id` must remove that argument. The associated enum types (`LinkListBulkOpsRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkBulkExportRequestTeamId`, `LinkBulkPauseRequestTeamId`) have also been removed from `vital.link`. Additionally, `connect_manual_provider` now accepts new optional parameters: `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`.
* **Breaking changes:**
* The `address` parameter of `UserClient.create_user()` (and its async counterpart) now requires a `UserAddress` object instead of `Address`. Update your imports and construction: replace `from vital import Address` with `from vital import UserAddress`.
* The `job_id` field has been removed from the `ParsingJob` model. Any code accessing `parsing_job.job_id` will raise an `AttributeError`.
* `Jpeg.content` and `Png.content` have changed from `str` to `bytes`.
**New features:**
* Three new top-level client namespaces are now available: `client.compendium`, `client.lab_account`, and `client.order_transaction` (sync and async).
* An optional `logging` parameter has been added to `Vital` and `AsyncVital` constructors, enabling configurable SDK-level logging via `LogConfig` or a custom `Logger`.
* New optional fields added to `ClientFacingInsulinInjectionSample` (`delivery_mode`, `delivery_form`, `bolus_purpose`), `ClientFacingOrder` (`clinical_notes`, `last_event`, `origin`, `order_transaction`), and `ResultMetadata` (`gender`); several previously required `ResultMetadata` fields are now optional.
* The SDK now includes three new API client namespaces: `lab_account` (retrieve team lab accounts), `order_transaction` (fetch order transactions, raw results, and PDF exports), and raw Compendium clients (`search` and `convert`). A structured logging framework (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is also now available from `vital.core` for SDK-level log configuration.
* The SDK now includes a new `RawOrderTransactionClient` (sync and async) for retrieving order transactions and their results via the `v3/order_transaction` endpoints. Approximately 40 new public types have been added, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `CompendiumSearchLabs`, `InsulinInjectionTimeseriesExpr`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new `InsulinInjectionTimeseriesExpr`, `ClientFacingInsulinInjectionSampleBolusPurpose`, `ClientFacingInsulinInjectionSampleDeliveryForm`, and `ClientFacingInsulinInjectionSampleDeliveryMode` types. Sonora Quest is now available as a provider and lab option across `AppointmentProvider`, `ClientFacingLabs`, and the new `CompendiumSearchLabs` enum. Additional new capabilities include derived readiness expressions (`DerivedReadinessColumnExpr`, `AwakeningsValueMacroExpr`), async appointment booking confirmation fields on `AppointmentBookingRequest`, a `recovery_readiness_score` on `ClientFacingSleep`, order transaction models (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), and lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`).
* The SDK now includes several new enumerations (`LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, `ParsingJobFailureReason`, `InsulinInjectionTimeseriesExprField`) and models (`OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, `RelatedCandidate`) to support expanded lab account management, order tracking, and data parsing workflows. New providers `TANDEM_SOURCE` and `SAMSUNG_HEALTH` are now available in `Providers`, `ManualProviders`, and `PasswordProviders`, and new lab values `SONORA_QUEST` and `CRL` have been added to `Labs`. Optional fields `access_notes` on patient address types and `order_transaction` on `LabResultsRaw` are also now available.
* The SDK now includes several new types and model extensions: `ResultMetadataGender`, `SearchMode`, and `SearchCompendiumResponse` for lab compendium search; `UsState` and `UserAddress` for structured US address handling; an optional `access_notes` field on `UsAddress`; and a new `RECOVERY_READINESS_SCORE` value in the `SleepColumnExprSleep` enum.
