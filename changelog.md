## 3.0.0 - 2026-04-01
* Several breaking changes have been made to public types in this release.
* The enum classes `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from `vital.link`. Any code importing or referencing these types will need to be updated.
* The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`; callers using the `.visit()` method must remove the `insulin_injection` callback argument. Additionally, `AppointmentPscLabs` has changed from a `Literal["quest"]` type to a `StrEnum` — existing strict type checks against the literal string may need to be updated, though the `"quest"` value is preserved as `AppointmentPscLabs.QUEST`. New capabilities include optional structured HTTP request/response logging (with automatic sensitive-header redaction), a `status_code` property on all HTTP response objects, and a `SONORA_QUEST` value in `AppointmentPscLabs`.
* The `file` parameter of `parser_create_job` (on both `LabReportClient` and `RawLabReportClient`) has changed from `core.File` to `typing.List[core.File]` — callers must now wrap a single file in a list (e.g. `file=[my_file]`). The following types have been removed from the top-level `vital` package: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`. New submodules `compendium`, `lab_account`, and `order_transaction` are now available, along with 40+ new types such as `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `UsState`, `UserAddress`, and more.
* The `get_psc_appointment_availability` method (on both `LabTestsClient` and `AsyncLabTestsClient`) now requires a new `lab: AppointmentPscLabs` parameter — existing callers must be updated to pass this argument. Additionally, several methods gain new optional parameters: `lab_account_id` and `lab_slug` on lab test creation, `order_transaction_id` on order listing, `appointment_notes` on phlebotomy appointment requests, `allow_stale` on PSC availability checks, `idempotency_key`/`idempotency_error` on PSC appointment booking, and `clinical_notes` on order creation.
* The SDK now supports additional optional parameters across lab test and order endpoints. New fields include `lab_slug` and `lab_account_id` on lab test creation, `lab_slug` on marker lookup, `order_transaction_id` on order listing, `appointment_notes` on at-home appointment scheduling, `clinical_notes` on order creation, and idempotency headers (`idempotency_key`, `idempotency_error`) on PSC appointment booking. The `get_psc_appointment_availability` method now accepts a required `lab` parameter (type `AppointmentPscLabs`) and an optional `allow_stale` flag, replacing a previously hardcoded `"quest"` value for the lab.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. Callers passing `team_id` as a keyword argument to any of these methods must remove that argument. The associated type classes (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have also been removed from `vital.link`.
* Additionally, `connect_manual_provider` now accepts optional `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` parameters, and the `ClientFacingActivity.wheelchair_use` field type has been narrowed from `Optional[bool]` to `Optional[Literal[True]]`.
* Several breaking changes have been introduced alongside new capabilities in this release.
**Breaking changes:**
* The `address` parameter in `UserClient.create_user()` (sync and async) has been renamed from `Address` to `UserAddress`. Update all call sites to import and pass a `UserAddress` instance instead.
* `Jpeg.content` and `Png.content` have changed type from `str` to `bytes`. Code that sets or reads these fields as strings will need to be updated.
* `ResultMetadata` fields `patient_first_name`, `patient_last_name`, `dob`, and `lab_name` are now optional (`None` by default); code that assumed these were always present must add null checks.
* `ParsingJob.job_id` has been removed; update any code accessing this field.
* `ClientFacingOrder.last_event` is now a required field; responses missing this field will fail validation.
**New features:**
* Three new sub-clients are available on the root `Vital`/`AsyncVital` client: `compendium` (search and convert lab tests), `lab_account`, and `order_transaction`.
* A new optional `logging` parameter (`LogConfig` or `Logger`) has been added to `Vital` and `AsyncVital` constructors to support configurable SDK-level logging.
* `ClientFacingInsulinInjectionSample` now includes optional `delivery_mode`, `delivery_form`, and `bolus_purpose` fields.
* `ClientFacingOrder` now includes optional `clinical_notes`, `origin`, and `order_transaction` fields.
* The SDK now includes three new client namespaces: `lab_account` (for retrieving team lab accounts), `order_transaction` (for fetching order transactions, results, and result PDFs), and raw compendium clients (`RawCompendiumClient` / `AsyncRawCompendiumClient`) for low-level compendium search and convert operations. A new configurable logging system (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is also available via `vital.core`. Additionally, OMIT sentinel values are now correctly excluded from serialized API request payloads.
* The SDK now includes a new `RawOrderTransactionClient` (sync and async) for retrieving order transactions, their results, and streaming PDF result downloads via the `v3/order_transaction` endpoints. Over 40 new public types have been added to `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `CompendiumSearchLabs`, `InsulinInjectionTimeseriesExpr`, `LabAccountStatus`, `UsState`, `UserAddress`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new types including `InsulinInjectionTimeseriesExpr`, `ClientFacingInsulinInjectionSampleBolusPurpose`, `ClientFacingInsulinInjectionSampleDeliveryForm`, and `ClientFacingInsulinInjectionSampleDeliveryMode`. A `recovery_readiness_score` field has been added to `ClientFacingSleep`, and derived readiness column expressions (`DerivedReadinessColumnExpr`) are now available in `AggregateExprArg`. Additional additions include Sonora Quest as a lab/appointment provider, order transaction and lab account management types, lab report parsing job webhook events, async appointment booking configuration fields, and a new `CompendiumSearchLabs` enum for compendium operations.
* The SDK now supports several new capabilities:
* New enums: `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`.
* New model types: `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`.
* New optional fields on `LabResultsRaw` (`order_transaction`) and all `PatientAddress` variants (`access_notes`).
* New provider/lab values: `TANDEM_SOURCE` and `SAMSUNG_HEALTH` in `Providers`/`ManualProviders`/`PasswordProviders`; `SONORA_QUEST` and `CRL` in `Labs`; `APERO` and `PVERIFY` in `PayorCodeExternalProvider`.
* New order status values: `CORRECTED`, `LAB_PROCESSING_BLOCKED` in `OrderLowLevelStatus` and corresponding entries in `OrderStatus`.
* `InsulinInjectionTimeseriesExpr`, `AwakeningsValueMacroExpr`, and `DerivedReadinessColumnExpr` are now included in the `QuerySelectItem` and `QueryGroupByItem` union types.
* The SDK now includes several new types: `ResultMetadataGender`, `SearchMode`, `SearchCompendiumResponse`, `UsState`, and `UserAddress` to support compendium search and address functionality. The `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains the new `RECOVERY_READINESS_SCORE` enum value.
