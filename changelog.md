## 3.0.0 - 2026-04-09
* The SDK now supports configurable HTTP request/response logging via a new `logging_config` parameter on the underlying HTTP clients, with automatic redaction of sensitive headers (e.g. `Authorization`, `x-api-key`). A `status_code` property has been added to `BaseHttpResponse` for direct access to the response status code. `AppointmentPscLabs` has been expanded to include `SONORA_QUEST` in addition to `QUEST`. The `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` types have been removed, and the `INSULIN_INJECTION` variant has been removed from `IntervalTimeseriesExprTimeseries`.
* The `parser_create_job` method's `file` parameter has been changed from `core.File` to `typing.List[core.File]` to support uploading multiple files in a single parse job — existing callers passing a single file must now wrap it in a list (e.g., `file=[my_file]`). The following previously exported types have been removed: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`. Many new types and submodules are now available, including `compendium`, `lab_account`, `order_transaction`, `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more.
* The `get_psc_appointment_availability()` method now requires a new `lab` parameter of type `AppointmentPscLabs`. Existing callers that do not pass this argument will receive a `TypeError`. Update all calls to include `lab=AppointmentPscLabs.QUEST` (or the appropriate lab value).
* Additionally, several methods gained new optional parameters: `lab_account_id` and `lab_slug` on lab test methods, `order_transaction_id` on order listing, `appointment_notes` on phlebotomy appointment requests, `idempotency_key` and `idempotency_error` on PSC appointment booking, and `clinical_notes` on order creation. Two new types, `AppointmentPscLabs` and `Labs`, are now available in the SDK.
* The `lab_tests` client now supports several new optional parameters across its endpoints:
* `lab_account_id` and `lab_slug` on lab test creation for scoping tests to a specific lab account or lab slug
* `lab_slug` on `get_markers` to look up markers by lab slug (takes precedence over `lab_id` when both are provided)
* `order_transaction_id` filter on order listing
* `appointment_notes` on home appointment creation
* `lab` (required, `AppointmentPscLabs`) and `allow_stale` on `get_psc_appointment_availability` — note that `lab` is no longer hardcoded to `"quest"` and must now be supplied by the caller
* `idempotency_key` and `idempotency_error` on PSC appointment booking for idempotent request support
* `clinical_notes` on order creation
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. The associated enum types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`) have also been removed — update any call sites and imports that reference them. Additionally, `connect_manual_provider` now accepts three new optional parameters: `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`.
* The `address` parameter of `UserClient.create_user_info()` (and `AsyncUserClient.create_user_info()`) now requires a `UserAddress` instance instead of an `Address` instance. Callers must replace `Address(...)` with `UserAddress(...)` — the fields are identical. Additionally, `Jpeg.content` and `Png.content` have changed type from `str` to `bytes`, and `ParsingJob.job_id` has been removed.
* New capabilities in this release: three new service clients are available as `client.compendium`, `client.lab_account`, and `client.order_transaction`. The `Vital` and `AsyncVital` constructors now accept an optional `logging` parameter for structured SDK logging. `ClientFacingOrder` gains `last_event`, `clinical_notes`, `origin`, and `order_transaction` fields. `ClientFacingInsulinInjectionSample` gains `delivery_mode`, `delivery_form`, and `bolus_purpose` fields. Several new `OrderStatus` enum values have been added, including corrected-result statuses.
* The SDK now includes two new API clients: `CompendiumClient` (with `search()` and `convert()` methods for lab test compendium operations) and `LabAccountClient` (with a `get_team_lab_accounts()` method). A new structured logging module is also available via `from vital.core import ILogger, ConsoleLogger, Logger, LogConfig, create_logger`.
* The SDK now includes an `order_transaction` client with three new methods: `get_transaction`, `get_transaction_result`, and `get_transaction_result_pdf`. Both synchronous (`OrderTransactionClient`) and asynchronous (`AsyncOrderTransactionClient`) variants are available, with optional raw-response access via `.with_raw_response`.
* The SDK now includes a broad set of new types and enum values supporting lab account management, order transactions, compendium search, enhanced insulin injection data, and appointment booking improvements. New types include `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `SearchCompendiumResponse`, `AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`, and many more. Appointment booking requests now support optional `appointment_notes`, `async_confirmation`, and confirmation timeout fields.
* The SDK now supports Sonora Quest (`SONORA_QUEST`) and CRL (`CRL`) as new lab options across `Labs`, `ClientFacingLabs`, and `CompendiumSearchLabs` enums. New models have been added for lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), insulin injection timeseries (`InsulinInjectionTimeseriesExpr`), derived readiness analytics (`DerivedReadinessColumnExpr`), and lab report parsing job webhook events. Additional enum values include `INSULIN_PUMP` for source type enums, `SAMSUNG_HEALTH` for manual providers, `CORRECTED` and `LAB_PROCESSING_BLOCKED` for order low-level status, and `DERIVED_READINESS` for index column expressions. New optional fields `recovery_readiness_score` (on `ClientFacingSleep`), `status_detail` (on `ClientFacingOrderEvent`), and `order_transaction` (on `LabResultsRaw`) are also available.
* The SDK now includes new types and capabilities across several domains. New `OrderStatusDetail`, `OrderSummary`, `OrderTransactionStatus`, `ParsingJobFailureReason`, `SearchMode`, `ResultMetadataGender`, `UsState`, and `UserAddress` types have been added. Lab compendium search is now supported via `SearchCompendiumResponse`, `PerLabCandidate`, `RelatedCandidate`, and `ProviderIdConversionResponse` models. Provider enums (`Providers`, `PasswordProviders`) now include `TANDEM_SOURCE` and `SAMSUNG_HEALTH`; `PayorCodeExternalProvider` adds `APERO` and `PVERIFY`. Address models (`PatientAddress`, `PatientAddressCompatible`, `PatientAddressWithValidation`, `UsAddress`) gain an optional `access_notes` field, and query expression union types are extended with `AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, and `InsulinInjectionTimeseriesExpr`.
