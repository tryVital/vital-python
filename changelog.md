## 3.0.0 - 2026-03-30
* Several type definitions have been removed from the SDK. The `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` enums are no longer available. Additionally, the `INSULIN_INJECTION` value has been removed from the `IntervalTimeseriesExprTimeseries` enum. The SDK now includes enhanced HTTP request logging capabilities and improved error handling with status code access on HTTP responses.
* The lab report parsing API now accepts multiple files instead of a single file, enabling batch processing of lab reports. New lab account management, compendium search, and order transaction modules provide expanded functionality for healthcare integrations.
* The SDK now supports additional optional parameters for enhanced lab test and appointment management. New parameters include lab account filtering (lab_account_id, lab_slug), clinical and appointment notes, order transaction ID filtering, and PSC appointment booking with idempotency support. The get_psc_appointment_availability() method now requires a lab parameter and supports stale data retrieval.
* The SDK now supports additional optional parameters for lab test operations including lab filtering by slug, order filtering by transaction ID, appointment notes, clinical notes, and idempotency support for PSC appointment booking. All existing code continues to work unchanged.
* The SDK has removed several optional parameters to simplify the API surface. The `team_id` parameter has been removed from bulk operations methods (`list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, `bulk_pause`), and the `vital_link_token` parameter has been removed from authentication methods (`token_state`, `email_auth`, `password_auth`, `generate_oauth_link`, `connect_password_provider`, `complete_password_provider_mfa`, `connect_email_auth_provider`, `get_all_providers`, `get_link_config`). The `connect_manual_provider` method now supports mobile SDK version tracking with new `vital_ios_sdk_version` and `vital_android_sdk_version` parameters, and accepts a `granted_permissions` parameter for fine-grained permission control.
* New client modules available: CompendiumClient for lab test search and conversion, LabAccountClient for lab account management, and OrderTransactionClient for order transaction operations. Enhanced insulin injection samples with delivery mode, form, and bolus purpose fields. Image content types now use bytes instead of strings for better type safety.
* New API clients available: CompendiumClient for lab test search and conversion operations, LabAccountClient for team lab account management, and OrderTransactionClient for comprehensive transaction and result handling including PDF downloads. The SDK also introduces configurable logging infrastructure with support for custom loggers and log levels.
* The SDK now includes a new `RawOrderTransactionClient` for managing order transactions, with methods to retrieve transaction details, results, and PDF reports. Additionally, 32 new type definitions have been added to support enhanced functionality including lab accounts, compendium search capabilities, and expanded expression types for data aggregation.
* The SDK now supports insulin injection data tracking with comprehensive delivery modes (basal/bolus) and bolus purposes (meal/correction/mixed). New lab report parsing job webhook events enable automated document processing workflows. Appointment booking now supports asynchronous confirmation with configurable timeouts and appointment notes. Added support for Sonora Quest lab provider and order transaction status tracking.
* The SDK now supports comprehensive lab testing workflows with new types for order tracking, account management, and transaction status. New provider integrations include Samsung Health and Tandem Source. Patient address types now include optional access notes for delivery instructions.
* New `UsState` enum and `UserAddress` model available for handling geographic address data. The `UsState` enum includes all 50 US state abbreviations with forward compatibility support.
