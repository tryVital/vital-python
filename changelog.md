## 3.0.0 - 2026-04-02
* Several breaking changes are included in this release:
* The `vital.link.types` subpackage and its exported types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed. Update any imports referencing these symbols.
* `IntervalTimeseriesExprTimeseries.INSULIN_INJECTION` and its corresponding `insulin_injection` parameter in the `visit()` method have been removed. Callers passing this argument to `visit()` must remove or replace it.
* `AppointmentPscLabs` has changed from a `Literal["quest"]` type alias to a `StrEnum` class with `QUEST` and `SONORA_QUEST` members. Update any isinstance checks or direct type references accordingly.
* New in this release: HTTP request/response logging with automatic sensitive-header redaction, a `status_code` property on response objects, and improved Server-Sent Event parsing utilities.
* **Breaking changes:**
* The `file` parameter of `parser_create_job` (on both `LabReportClient` and `AsyncLabReportClient`) has changed from a single `core.File` to `typing.List[core.File]`. Callers must wrap their existing file argument in a list: `file=[my_file]`.
* The previously exported types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from the top-level package exports.
**New features:**
* The SDK now exposes new submodules (`compendium`, `lab_account`, `order_transaction`) and many new types, including `AwakeningsValueMacroExpr`, `CanonicalCandidate`, `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and others. An optional `logging` parameter has also been added to client constructors.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` (e.g. `AppointmentPscLabs.QUEST`). Existing callers that do not pass this argument will receive a `TypeError` at runtime.
* Additional optional parameters have been added across several lab test methods: `lab_slug` and `lab_account_id` on `create_lab_test`, `lab_slug` on `get_markers`, `order_transaction_id` on order listing, `appointment_notes` on `request_phlebotomy_appointment`, `allow_stale` on `get_psc_appointment_availability`, `idempotency_key` and `idempotency_error` on `book_psc_appointment`, and `clinical_notes` on `create_order`. Two new types, `AppointmentPscLabs` and `Labs`, are now available in the SDK.
* The `get_psc_appointment_availability` method now requires a `lab` parameter (type `AppointmentPscLabs`) that was previously hardcoded to `"quest"`. Callers must update their invocations to pass an explicit `lab` value (e.g. `AppointmentPscLabs.QUEST`).
* Several new optional parameters have also been added across lab test and appointment methods: `lab_slug` and `lab_account_id` on create-lab-test, `lab_slug` on get-markers, `order_transaction_id` on list-orders, `appointment_notes` on book-at-home-appointment, `allow_stale` on get-PSC-availability, `idempotency_key`/`idempotency_error` on book-PSC-appointment, and `clinical_notes` on create-order. New types `AppointmentPscLabs` and `Labs` are now exported.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause` (both sync and async). Callers passing `team_id` as a keyword argument will encounter a `TypeError`. The associated enum types (`LinkListBulkOpsRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkBulkExportRequestTeamId`, `LinkBulkPauseRequestTeamId`) have also been removed and any imports of them must be deleted.
* New optional parameters `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` have been added to `connect_manual_provider`, enabling richer mobile SDK context to be passed when connecting a manual provider.
* The `address` parameter in `UserClient.create_user()` (and its async counterpart) now requires a `UserAddress` instance instead of the former `Address` type — update imports and construction calls accordingly. The `ParsingJob` model no longer includes the `job_id` field (breaking removal), and the `Jpeg` and `Png` models now represent `content` as `bytes` instead of `str`.
* Three new top-level service clients are now available: `client.compendium` (search and convert lab compendium entries), `client.lab_account`, and `client.order_transaction`. Both `Vital` and `AsyncVital` constructors now accept an optional `logging` parameter for SDK-level log configuration. `ClientFacingOrder` gains `last_event`, `clinical_notes`, `origin`, and `order_transaction` fields, and `ClientFacingInsulinInjectionSample` gains `delivery_mode`, `delivery_form`, and `bolus_purpose` fields.
* The SDK now includes three new client namespaces: `lab_account` for retrieving team lab accounts, `order_transaction` for fetching order transaction details and PDF results, and expanded `compendium` raw clients for searching and converting compendium data. A new structured logging system (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is also available from `vital.core` for configurable SDK-level logging.
* The SDK now includes a new `RawOrderTransactionClient` (and async variant) providing `get_transaction`, `get_transaction_result`, and `get_transaction_result_pdf` methods for the `v3/order_transaction` endpoints. Approximately 40 new types are available in `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `CompendiumSearchLabs`, `ProviderIdConversionResponse`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new `ClientFacingInsulinInjectionSample*` enums (BolusPurpose, DeliveryForm, DeliveryMode) and the `InsulinInjectionTimeseriesExpr` aggregate expression type. New lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `ConvertCompendiumResponse`) and order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`) are now available. Additional additions include Sonora Quest support across lab and appointment provider enums, a `recovery_readiness_score` field on `ClientFacingSleep`, appointment booking enhancements (notes, async confirmation options), lab report parsing job event types, and a `DerivedReadinessColumnExpr` type for readiness metrics aggregation.
* The SDK now includes several new enums (`InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, `ParsingJobFailureReason`) and new models (`OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, `RelatedCandidate`). New enum values have been added to `Labs` (`SONORA_QUEST`, `CRL`), `Providers` and `ManualProviders` (`SAMSUNG_HEALTH`), `PasswordProviders` and `Providers` (`TANDEM_SOURCE`), `PayorCodeExternalProvider` (`APERO`, `PVERIFY`), `OrderLowLevelStatus` (`CORRECTED`, `LAB_PROCESSING_BLOCKED`), and `OrderStatus` (multiple `corrected` and `lab_processing_blocked` statuses). Existing models `PatientAddress`, `PatientAddressCompatible`, and `PatientAddressWithValidation` gain an optional `access_notes` field, and `LabResultsRaw` gains an optional `order_transaction` field.
* The SDK now includes several new types to support compendium search and address functionality. A new `SearchCompendiumResponse` model, `SearchMode` enum, `ResultMetadataGender` enum, `UsState` enum, and `UserAddress` model have been added. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains a new `RECOVERY_READINESS_SCORE` enum value.
