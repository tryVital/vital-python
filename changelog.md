## 3.0.0 - 2026-03-18
* The SDK now supports optional HTTP request logging for debugging and monitoring API interactions. Pass a `LogConfig` or `Logger` instance to the `logging` parameter when creating client instances. All sensitive headers (authorization, API keys, etc.) are automatically redacted in logs. The `AppointmentPscLabs` type has been converted to a proper enum with additional values and visitor pattern support. Lab report parsing now accepts multiple files in a single request.
* The SDK now supports additional filtering options for lab tests and enhanced appointment booking capabilities. New parameters include lab account filtering, lab slug-based queries, order transaction ID filtering, appointment notes, clinical notes for orders, and idempotency support for PSC appointment booking.
* The SDK now supports lab-specific filtering with new `lab_account_id` and `lab_slug` parameters for lab test operations. Appointment booking has been enhanced with support for appointment notes, clinical notes, and idempotency keys. The Link client methods no longer require the `vital_link_token` parameter as it's now automatically handled. Manual provider connections now accept mobile SDK version information and granted permissions.
* The `create_user` method now requires a `UserAddress` parameter instead of `Address`. Replace `Address` imports and usage with `UserAddress` which provides the same fields but is specifically typed for user contexts. New client modules are available: `compendium`, `lab_account`, and `order_transaction` for expanded SDK functionality.
* New lab test compendium and account management clients are now available. The CompendiumClient provides search() and convert() methods for discovering lab tests and converting between providers like LabCorp and Quest. The LabAccountClient offers get_team_lab_accounts() for managing configured lab accounts.
* New `OrderTransactionClient` with methods for retrieving lab test transactions, results, and PDF reports. New `LabAccountClient` for discovering and filtering team lab accounts. Manual provider connections now accept optional SDK version headers and granted permissions parameter.
* The SDK now supports lab compendium search with canonical candidate matching, order transaction management with status tracking, and enhanced appointment booking with configurable async confirmation and timeout options. Added support for Sonora Quest lab provider and new derived readiness analytics capabilities.
* The SDK now supports derived readiness data analysis with new DerivedReadinessColumnExpr types. Additional enum values have been added across Labs, Providers, and ManualProviders for expanded service integration. New order transaction and lab account management types provide enhanced tracking capabilities. Address types now include an optional access_notes field for location-specific information.
* The SDK now includes two new public types: `UsState` enum for US state representation with all 50 state codes, and `UserAddress` model for structured address data. Both types include forward compatibility for future API changes.
