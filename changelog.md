## 3.0.0 - 2026-04-09
* The SDK now includes opt-in HTTP request/response logging via a new `LogConfig`/`Logger` interface on `HttpClient` and `AsyncHttpClient`, with automatic redaction of sensitive headers. `AppointmentPscLabs` has been expanded to a full enum supporting `QUEST` and `SONORA_QUEST` values. `BaseHttpResponse` now exposes a `status_code` property.
**Breaking changes:** The public enums `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from `vital.link`. The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`. Update any code that references these symbols.
* The `parser_create_job` method on `LabReportClient` now accepts multiple files: the `file` parameter has changed from `core.File` to `typing.List[core.File]`. Update existing calls from `file=my_file` to `file=[my_file]`.
* The following types have been removed from the top-level `vital` package: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`.
* New submodules (`compendium`, `lab_account`, `order_transaction`) and many new types are now available, including `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and others. An optional `logging` parameter has also been added to the sync and async client wrappers.
* The `get_psc_appointment_availability` method (both sync and async) now requires a `lab` parameter of type `AppointmentPscLabs` to specify which lab to check for availability. Existing callers must add `lab=AppointmentPscLabs.QUEST` (or the appropriate value) to their calls.
* Several new optional parameters have also been added across the `LabTestsClient`: `lab_account_id` and `lab_slug` on `create_lab_test`; `lab_slug` on `get_markers`; `order_transaction_id` on `get_orders`; `appointment_notes` on `request_phlebotomy_appointment`; `allow_stale` on `get_psc_appointment_availability`; `idempotency_key` and `idempotency_error` on `book_psc_appointment`; and `clinical_notes` on `create_order`.
* The lab tests and orders clients now support several new optional parameters. `get_psc_appointment_availability` accepts a new required `lab` parameter (of type `AppointmentPscLabs`) replacing the previously hardcoded `"quest"` value, plus an optional `allow_stale` flag. Lab test creation now accepts `lab_account_id` and `lab_slug`; `get_markers` accepts `lab_slug`; order listing accepts `order_transaction_id`; PSC appointment creation accepts `appointment_notes`; order creation accepts `clinical_notes`; and PSC appointment booking supports idempotency via `idempotency_key` and `idempotency_error` (closed beta).
* The `team_id` parameter has been removed from all bulk link operations: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. Callers passing `team_id` to any of these methods must remove that argument. The associated enum types (`LinkListBulkOpsRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkBulkExportRequestTeamId`, `LinkBulkPauseRequestTeamId`) have also been removed from `vital.link`.
* The `connect_manual_provider` method now accepts three new optional parameters: `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`, enabling richer mobile SDK context when connecting manual providers.
* The `address` parameter type in `UserClient.create_user()` (and its async/raw variants) has changed from `Address` to `UserAddress`. Callers must update their imports and replace `Address(...)` with `UserAddress(...)`.
* Additionally, the `job_id` field has been removed from `ParsingJob`, and `Jpeg.content` / `Png.content` have changed from `str` to `bytes`. The SDK also adds three new sub-clients — `compendium`, `lab_account`, and `order_transaction` — accessible directly from `Vital` and `AsyncVital`, along with an optional `logging` parameter on both clients.
* The SDK now includes two new top-level client namespaces: `lab_account` and `order_transaction`. Use `client.lab_account.get_team_lab_accounts()` to retrieve team lab accounts, and `client.order_transaction.get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()` to manage order transactions. A new `vital.core` logging framework (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is also available for configurable SDK-level logging.
* The SDK now includes a new `RawOrderTransactionClient` (sync and async) for retrieving order transactions and results via the `/v3/order_transaction` endpoints. Approximately 40 new public types have been added, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and others. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new types including `InsulinInjectionTimeseriesExpr`, `ClientFacingInsulinInjectionSampleBolusPurpose`, `ClientFacingInsulinInjectionSampleDeliveryForm`, and `ClientFacingInsulinInjectionSampleDeliveryMode`. New lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`) and order transaction types (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`) are now available. Sonora Quest has been added as a supported appointment provider and lab (`AppointmentProvider.SONORA_QUEST`, `ClientFacingLabs.SONORA_QUEST`). Sleep data now includes a `recovery_readiness_score` field, and appointment booking requests support new optional fields for async confirmation and notes.
* The SDK now supports several new enums and models for lab testing, order management, and data sources. New enums include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`. New models include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`. Existing enums and models have been expanded with new values and optional fields, including `SAMSUNG_HEALTH` and `TANDEM_SOURCE` provider support, new `access_notes` field on patient address types, and additional order status and lab entries.
* The SDK now includes several new types: `ResultMetadataGender`, `SearchMode`, `SearchCompendiumResponse`, `UsState`, and `UserAddress`. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains the `RECOVERY_READINESS_SCORE` enum value.
