## 3.0.0 - 2026-04-09
* Several breaking changes have been made in this release:
* The `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` enum classes have been removed. Update any imports or references to these types accordingly.
* The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`. Callers using `.visit()` must also remove the `insulin_injection` keyword argument.
* `AppointmentPscLabs` has changed from a `Literal["quest"]` type alias to a full `StrEnum` class with `QUEST` and `SONORA_QUEST` values; code that relied on the literal string type annotation may need to be updated.
* New in this release: HTTP requests now emit structured debug and error log messages (with automatic redaction of sensitive headers), and `BaseHttpResponse` exposes a new `status_code` property.
* **Breaking changes:**
* The `file` parameter of `lab_report.parser_create_job()` (both sync and async) has changed from a single `core.File` to `typing.List[core.File]`. Update existing calls by wrapping the file in a list: `file=[my_file]`.
* The following types have been removed from the top-level SDK exports: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`.
**New additions:**
* The SDK now exposes over 40 new types including `AwakeningsValueMacroExpr`, `CanonicalCandidate`, `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more. Three new submodules are also available: `compendium`, `lab_account`, and `order_transaction`. An optional `logging` parameter is now supported on the client wrapper for configurable request logging.
* The `get_psc_appointment_availability` method now requires a new `lab` parameter of type `AppointmentPscLabs` (e.g. `AppointmentPscLabs.QUEST`). Existing callers that do not pass this argument will receive a `TypeError`. Update all calls to include the `lab` argument.
* Additional optional parameters have been added across several lab test methods: `lab_account_id` and `lab_slug` on `create_lab_test`, `lab_slug` on `get_markers`, `order_transaction_id` on `get_orders`, `appointment_notes` on `request_phlebotomy_appointment`, `allow_stale` on `get_psc_appointment_availability`, `idempotency_key` and `idempotency_error` on `book_psc_appointment`, and `clinical_notes` on `create_order`. Two new types — `AppointmentPscLabs` and `Labs` — are now available.
* The `get_psc_appointment_availability` method now accepts a required `lab` parameter (type `AppointmentPscLabs`) instead of hardcoding the lab to `"quest"`, allowing callers to specify which lab to check availability for. Several new optional parameters have also been added across lab test and appointment APIs: `lab_slug` and `lab_account_id` on lab test creation, `lab_slug` on marker listing, `order_transaction_id` on order listing, `appointment_notes` on home phlebotomy booking, `allow_stale` on PSC availability, `idempotency_key`/`idempotency_error` headers on PSC appointment booking, and `clinical_notes` on order creation.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. Callers passing `team_id` (including the now-removed `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` types) must remove that argument. The `connect_manual_provider` method now accepts three new optional parameters: `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`.
* The SDK now exposes two new sub-clients: `lab_account` (with `get_team_lab_accounts()`) and `order_transaction` (with `get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()`). A raw HTTP response variant of the compendium client (`RawCompendiumClient`) is also available. Additionally, a new structured logging framework (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) has been added to `vital.core` for configurable SDK-level logging.
* The SDK now includes a new `RawOrderTransactionClient` (sync and async) for interacting with the `v3/order_transaction/` API, supporting retrieval of transaction details, raw lab results, and PDF result streaming. Approximately 40 new public types have been added, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `OrderSummary`, `SearchCompendiumResponse`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data, with new `InsulinInjectionTimeseriesExpr`, `ClientFacingInsulinInjectionSampleBolusPurpose`, `ClientFacingInsulinInjectionSampleDeliveryForm`, and `ClientFacingInsulinInjectionSampleDeliveryMode` types. Sleep data now includes a `recovery_readiness_score` field on `ClientFacingSleep`. Lab testing gains Sonora Quest support across `AppointmentProvider`, `ClientFacingLabs`, and the new `CompendiumSearchLabs` enum, plus new types for lab accounts (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), order transactions (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), compendium conversion (`ConvertCompendiumResponse`, `CanonicalCandidate`), and lab report parsing job events. Appointment booking and rescheduling requests now accept `appointment_notes`, and booking supports async confirmation timeout controls.
* The SDK now includes several new types and expanded enum values to support broader lab testing workflows, order tracking, and provider integrations. New enums include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`. New models include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`. Existing enums such as `Labs`, `Providers`, `ManualProviders`, `PasswordProviders`, `OrderLowLevelStatus`, `OrderStatus`, and `PayorCodeExternalProvider` have been extended with new values, and optional fields `access_notes` and `order_transaction` have been added to address and lab result models respectively.
* The SDK now includes new types to support lab compendium search: `SearchCompendiumResponse` and `SearchMode`. A new `UsState` enum, `UserAddress` model, and `ResultMetadataGender` enum have also been added. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains a new `RECOVERY_READINESS_SCORE` value.
