## 3.0.0 - 2026-04-08
* The SDK now includes structured HTTP request/response logging with automatic redaction of sensitive headers (e.g., `authorization`, `x-api-key`, `cookie`). Pass a `LogConfig` or `Logger` instance when constructing the client to enable logging.
* `AppointmentPscLabs` has been expanded from a plain `Literal["quest"]` to a full enum with `QUEST` and `SONORA_QUEST` values. The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`. The `Link` bulk operation team ID types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed. Callers referencing these types or the `insulin_injection` enum member or `visit()` callback must be updated.
* Several breaking changes are included in this release:
**`parser_create_job` now requires a list of files.** The `file` parameter on both `LabReportClient.parser_create_job` and `AsyncLabReportClient.parser_create_job` has changed from `core.File` to `typing.List[core.File]`. Wrap any existing single-file argument in a list (e.g. `file=[my_file]`).
**Five `Link` request types have been removed.** The following exports are no longer available: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`.
* New additions include the `compendium`, `lab_account`, and `order_transaction` submodules; an optional `logging` parameter on the sync and async clients for configurable HTTP logging; and many new model types such as `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderOrigin`, `OrderSummary`, `UsState`, `UserAddress`, and more.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` (e.g., `AppointmentPscLabs.QUEST`). Existing callers must be updated to pass this new required argument. Several other methods on `LabTestsClient` and `AsyncLabTestsClient` have been expanded with new optional parameters: `lab_slug` and `lab_account_id` on `create_lab_test`, `lab_slug` on `get_markers`, `order_transaction_id` on `get_orders`, `appointment_notes` on `request_phlebotomy_appointment`, `allow_stale` on `get_psc_appointment_availability`, `idempotency_key` and `idempotency_error` on `book_psc_appointment`, and `clinical_notes` on `create_order`.
* The lab tests client now supports several new optional parameters across multiple methods: `lab_account_id` and `lab_slug` on lab test creation, `lab_slug` on `get_markers` for filtering by lab slug, `order_transaction_id` on order listing, `appointment_notes` on PSC appointment scheduling, `clinical_notes` on order creation, and `idempotency_key`/`idempotency_error` on PSC appointment booking (closed beta). The `get_psc_appointment_availability` method now accepts an explicit required `lab` parameter (type `AppointmentPscLabs`) instead of a hardcoded value, and an `allow_stale` optional parameter to allow cached availability data.
* The `team_id` parameter has been removed from the following `link` client methods: `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause`. Callers that currently pass `team_id` to any of these methods must remove that argument. The associated enum types (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have also been removed from the `vital.link` namespace.
* New optional parameters `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` have been added to `connect_manual_provider` to support mobile SDK version reporting and permission scoping.
* Several breaking changes are included in this release:
* **`create_user()` address parameter**: The `address` parameter type has changed from `Address` to `UserAddress`. Replace `from vital import Address` with `from vital import UserAddress` and update any `Address(...)` instantiations to `UserAddress(...)`.
* **`ParsingJob.job_id` removed**: The `job_id` field has been removed from `ParsingJob`. A new optional `failure_reason` field has been added.
* **`Jpeg.content` and `Png.content` changed from `str` to `bytes`**: Code that treats image content as a string will need to be updated to handle `bytes`.
* New capabilities also included in this release:
* Three new sub-clients are now available: `client.compendium` (search and convert lab tests), `client.lab_account`, and `client.order_transaction`.
* Both `Vital` and `AsyncVital` now accept an optional `logging` parameter (`LogConfig` or `Logger`) for SDK-level log configuration.
* `ClientFacingOrder` now exposes `last_event`, `clinical_notes`, `origin`, and `order_transaction` fields.
* `ClientFacingInsulinInjectionSample` now includes optional `delivery_mode`, `delivery_form`, and `bolus_purpose` fields.
* `ResultMetadata` fields (`patient_first_name`, `patient_last_name`, `dob`, `lab_name`) are now optional, and a new optional `gender` field has been added.
* The SDK now includes two new client namespaces: `lab_account` (with `get_team_lab_accounts()`) and `order_transaction` (with `get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()`). A new `RawCompendiumClient` is also available via `compendium.with_raw_response` for direct access to raw HTTP responses on compendium search and convert operations. Additionally, a structured logging system (`ILogger`, `ConsoleLogger`, `LogConfig`, `LogLevel`, `Logger`, `create_logger`) has been added to `vital.core`.
* The SDK now includes a new `RawOrderTransactionClient` (and async variant) for retrieving order transaction details, lab results, and PDF reports via the `v3/order_transaction` endpoints. Dozens of new public types are now available in `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `UserAddress`, `UsState`, `ParsingJobFailureReason`, and more. The `Address` model also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data, derived readiness columns, and order transaction tracking. New lab-related types have been added including `ClientFacingLabAccount`, `GetTeamLabAccountsResponse`, `ConvertCompendiumResponse`, and `CompendiumSearchLabs` (with Sonora Quest support). Appointment booking and reschedule requests now accept optional `appointment_notes` and async confirmation configuration fields, and `ClientFacingSleep` exposes a new optional `recovery_readiness_score` field.
* The SDK now includes several new types and expanded enumerations to support broader lab testing workflows, additional data providers, and richer query capabilities.
* New enums include `InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason`. New model types include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate`.
* Existing enums are expanded: `Labs` gains `SONORA_QUEST` and `CRL`; `Providers` and `ManualProviders` gain `SAMSUNG_HEALTH`; `Providers` and `PasswordProviders` gain `TANDEM_SOURCE`; `OrderLowLevelStatus` and `OrderStatus` gain corrected and lab-processing-blocked statuses; `PayorCodeExternalProvider` gains `APERO` and `PVERIFY`. Additionally, `LabResultsRaw` has a new optional `order_transaction` field and patient address models gain an optional `access_notes` field.
* The SDK now includes new types to support lab compendium search (`SearchCompendiumResponse`, `SearchMode`), a `ResultMetadataGender` enum, a `UsState` enum for all 50 US states, and a `UserAddress` model. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` now includes the `RECOVERY_READINESS_SCORE` value.
