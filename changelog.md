## 3.0.0 - 2026-04-13
* Several breaking changes have been made in this release:
* The types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed from `vital.link` and `vital.link.types`. Remove any imports or usages of these types from your code.
* The `INSULIN_INJECTION` member has been removed from the `IntervalTimeseriesExprTimeseries` enum, and its corresponding `insulin_injection` parameter has been removed from the `visit()` method. Update any `visit()` call sites accordingly.
* `AppointmentPscLabs` has changed from a `Literal["quest"]` type alias to a `StrEnum` class with `QUEST` and `SONORA_QUEST` members; update type annotations and usages as needed.
* New in this release: HTTP requests and responses now emit structured debug/error log messages (with sensitive headers automatically redacted), and `BaseHttpResponse` now exposes a `status_code` property.
* The `parser_create_job` method on `LabReportClient` and `AsyncLabReportClient` now accepts `file: typing.List[core.File]` (a list of files) instead of a single `core.File`. Callers must wrap their existing single-file argument in a list.
* The following previously exported types have been removed: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`.
* Three new sub-modules are now available — `compendium`, `lab_account`, and `order_transaction` — along with over 40 new types including `ClientFacingOrderTransaction`, `OrderSummary`, `SearchCompendiumResponse`, `LabAccountStatus`, `InsulinInjectionTimeseriesExpr`, and more. The SDK client also now accepts an optional `logging` configuration parameter.
* The `get_psc_appointment_availability` method now requires a `lab` parameter of type `AppointmentPscLabs` (e.g., `AppointmentPscLabs.QUEST`). Existing callers must be updated to pass this new required argument.
* Additionally, the following new optional parameters have been added across the `LabTestsClient`:
* `lab_account_id` and `lab_slug` on `create_lab_test`
* `lab_slug` on `get_markers`
* `order_transaction_id` on order listing methods
* `appointment_notes` on `request_phlebotomy_appointment`
* `allow_stale`, `idempotency_key`, and `idempotency_error` on PSC appointment methods
* `clinical_notes` on `create_order`
* Two new types, `AppointmentPscLabs` and `Labs`, are now exported from the SDK.
* The `get_psc_appointment_availability` method on `LabTestsClient` now requires a `lab` parameter (type `AppointmentPscLabs`) to specify which lab to check availability for. Previously, this was hardcoded to `"quest"`. Existing callers must update their code to pass this argument explicitly.
* Additional new optional parameters have been added across lab test and appointment methods: `lab_slug` and `lab_account_id` on lab test create/update and marker listing, `order_transaction_id` on order listing, `appointment_notes` on appointment scheduling, `allow_stale` on PSC availability, `idempotency_key` and `idempotency_error` on PSC appointment booking (closed beta), and `clinical_notes` on order creation.
* The `team_id` parameter has been removed from `link.list_bulk_ops()`, `link.bulk_import()`, `link.bulk_trigger_historical_pull()`, `link.bulk_export()`, and `link.bulk_pause()`. Callers passing `team_id` must remove that argument. The associated enum types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have also been removed from `vital.link`; any imports of these types must be deleted.
* `link.connect_manual_provider()` now accepts two new optional parameters — `vital_ios_sdk_version` and `vital_android_sdk_version` (sent as request headers) — and a new optional `granted_permissions` body field.
* Several breaking changes are included in this release:
* The `address` parameter of `create_user` (and the `UserInfo.address` field) now requires `UserAddress` instead of `Address`. Update any code that imports or passes an `Address` object to use `UserAddress` instead.
* `Jpeg.content` and `Png.content` have changed from `str` to `bytes`. Code that treats these fields as strings will need to be updated.
* `ResultMetadata` fields `patient_first_name`, `patient_last_name`, `dob`, and `lab_name` are now optional (`None` instead of `str`). Callers that assume these are always present should add null checks.
* `ParsingJob.job_id` has been removed. Code accessing this field will raise an `AttributeError`.
* New capabilities also included: `compendium`, `lab_account`, and `order_transaction` sub-clients are now available on `Vital` and `AsyncVital`; a new optional `logging` parameter is available on both client constructors; `ClientFacingOrder` gains `last_event`, `clinical_notes`, `origin`, and `order_transaction` fields; `ClientFacingInsulinInjectionSample` gains `delivery_mode`, `delivery_form`, and `bolus_purpose` fields; and several new `OrderStatus` enum values have been added.
* The SDK now includes two new resource clients: `CompendiumClient` (accessible via `client.compendium`) with `search()` and `convert()` methods for querying and cross-lab converting lab test compendium entries, and `LabAccountClient` (accessible via `client.lab_account`) with a `get_team_lab_accounts()` method. A new structured logging framework (`ILogger`, `ConsoleLogger`, `Logger`, `LogConfig`, `LogLevel`, `create_logger`) is also available from `vital.core`.
* The SDK now includes an `order_transaction` client with three new methods: `get_transaction()`, `get_transaction_result()`, and `get_transaction_result_pdf()`. Both synchronous (`OrderTransactionClient`) and asynchronous (`AsyncOrderTransactionClient`) variants are available, supporting retrieval of order transaction details, raw lab results, and streamed PDF reports.
* The SDK now exposes a large set of new types and enums to support expanded lab account management, order transactions, compendium search, insulin injection details, and appointment workflow enhancements. New types include `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, `ProviderIdConversionResponse`, `AwakeningsValueMacroExpr`, `DerivedReadinessColumnExpr`, `InsulinInjectionTimeseriesExpr`, and many more. New enum values `SONORA_QUEST` (AppointmentProvider), `INSULIN_PUMP` (device/ECG source types), and new optional fields on `Address`, `AppointmentBookingRequest`, `AppointmentRescheduleRequest`, and `ClientFacingAppointment` are also included.
* The SDK now supports lab account management with the new `ClientFacingLabAccount`, `LabAccountStatus`, and `LabAccountDelegatedFlow` types, and order transactions via `ClientFacingOrderTransaction` and `GetOrderTransactionResponse`. New enum values have been added: `SONORA_QUEST` in `ClientFacingLabs` and `Labs`, `CRL` in `Labs`, `SAMSUNG_HEALTH` in `ManualProviders`, `INSULIN_PUMP` in `ClientFacingMenstrualCycleSourceType` and `ClientFacingSleepCycleSourceType`, and `CORRECTED`/`LAB_PROCESSING_BLOCKED` in `OrderLowLevelStatus`. New optional fields `recovery_readiness_score` on `ClientFacingSleep`, `status_detail` on `ClientFacingOrderEvent`, and `order_transaction` on `LabResultsRaw` are also available. Insulin injection timeseries and derived readiness query expressions are now supported.
* The SDK now includes several new types and expanded enumerations. New Pydantic models include `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, `RelatedCandidate`, `SearchCompendiumResponse`, and `UserAddress`. New enums include `OrderStatusDetail`, `OrderTransactionStatus`, `ParsingJobFailureReason`, `ResultMetadataGender`, `SearchMode`, and `UsState`. Existing enums have been extended with new values (`tandem_source`, `samsung_health`, `apero`, `pverify`, `recovery_readiness_score`), and address models now support an optional `access_notes` field.
