## 3.0.0 - 2026-04-01
* Several breaking changes have been made to public types in this release:
* **`IntervalTimeseriesExprTimeseries`**: The `INSULIN_INJECTION` enum member and its corresponding `visit()` callback parameter have been removed. Callers using `.visit(insulin_injection=...)` will receive a `TypeError`.
* **`vital.link` module**: The public types `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId` have been removed. Any code importing these types should be updated accordingly.
* **`AppointmentPscLabs`**: Previously a `Literal["quest"]` type alias, this is now a `StrEnum` class with `QUEST` and `SONORA_QUEST` members. Code using `AppointmentPscLabs` as a type annotation or passing the string `"quest"` directly may need to be updated to use `AppointmentPscLabs.QUEST`.
* New additions include a `status_code` property on `BaseHttpResponse` and opt-in structured HTTP request/response logging with automatic redaction of sensitive headers.
* **Breaking changes in this release:**
* 1. The `file` parameter of `LabReportClient.parser_create_job` (sync and async) has changed from `core.File` to `typing.List[core.File]`. Existing callers must wrap their file in a list: `file=[my_file]`.
* 2. The following symbols have been removed from the public API: `LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkListBulkOpsRequestTeamId`. Remove any imports or references to these types.
**New in this release:**
* The SDK now includes three new submodule namespaces (`compendium`, `lab_account`, `order_transaction`) and over 40 new public types covering lab accounts, order transactions, insulin injection details, compendium search, and more. Client wrappers now accept an optional `logging` parameter for structured request/response logging.
* The `LabTestsClient` (sync and async) has been expanded with new optional parameters across several methods:
* `get_markers()` now accepts `lab_slug` for filtering markers by lab slug, and its documentation clarifies that reflex markers are excluded.
* `get_psc_appointment_availability()` now requires a `lab` parameter (`AppointmentPscLabs`) and accepts an optional `allow_stale` flag to permit cached availability data.
* `book_psc_appointment()` now accepts optional `idempotency_key` and `idempotency_error` parameters for idempotency support (closed beta).
* `request_phlebotomy_appointment()` now accepts an optional `appointment_notes` parameter.
* `create_order()` now accepts an optional `clinical_notes` parameter.
* Lab test creation methods now accept optional `lab_account_id` and `lab_slug` parameters.
* Order listing now supports filtering by `order_transaction_id`.
* New types `AppointmentPscLabs` and `Labs` are now available.
* The lab tests and appointment APIs now support several new optional parameters. Notably, `get_psc_appointment_availability` now accepts a `lab` parameter (of the new `AppointmentPscLabs` type) instead of defaulting to a hardcoded value, and PSC appointment booking now supports optional `idempotency_key` and `idempotency_error` parameters for idempotent requests. Additional optional fields — `lab_slug`, `lab_account_id`, `order_transaction_id`, `appointment_notes`, and `clinical_notes` — have been added to various lab test and order methods.
* The `team_id` parameter has been removed from the `list_bulk_ops`, `bulk_import`, `bulk_trigger_historical_pull`, `bulk_export`, and `bulk_pause` methods on `LinkClient` and `AsyncLinkClient`. Callers passing `team_id` to any of these methods must remove that argument. The associated type classes (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have also been removed. Additionally, `connect_manual_provider` now accepts new optional parameters: `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions`.
* The `address` parameter in user-creation methods (`UserClient.create_user`, `AsyncUserClient.create_user`, and their raw variants) now requires a `UserAddress` instance instead of the former `Address` type — callers using `Address` will receive a type error and must update their imports and usage to `UserAddress`.
* The `Jpeg.content` and `Png.content` fields have changed from `str` to `bytes`, which is a breaking change for any code that assigns or reads those fields as strings. The `ParsingJob.job_id` field has been removed; code that accesses `job_id` will raise an `AttributeError`.
* Additionally, the SDK gains three new client namespaces — `compendium`, `lab_account`, and `order_transaction` — on both `Vital` and `AsyncVital`, an optional `logging` parameter on both clients, new optional fields on `ClientFacingOrder` (including the required `last_event`), `ClientFacingInsulinInjectionSample`, and `ResultMetadata`, and several fields narrowed to literal types for improved type safety.
* The SDK now includes three new client modules: `lab_account` for retrieving team lab accounts, `order_transaction` for fetching order transaction details and streaming result PDFs, and expanded compendium raw clients (`search` and `convert`). A new structured logging framework (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is also available via `vital.core` for configurable log-level filtering.
* The SDK now includes a new `RawOrderTransactionClient` (and its async counterpart) for retrieving order transaction details, raw lab results, and streaming PDF reports via the `v3/order_transaction` endpoints. Approximately 40 new public types have been added to `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `SearchCompendiumResponse`, and more. The `Address` model now exposes an optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new expression types (`InsulinInjectionTimeseriesExpr`) and associated enums for bolus purpose, delivery form, and delivery mode. A new `recovery_readiness_score` field is available on `ClientFacingSleep`, and a new `DerivedReadinessColumnExpr` enables derived readiness queries. Order transaction tracking is now available via `ClientFacingOrderTransaction` and `GetOrderTransactionResponse`, and appointment booking requests now accept optional async confirmation and notes fields. Sonora Quest has been added as a supported lab and appointment provider.
* The SDK now includes new enumerations (`InsulinInjectionTimeseriesExprField`, `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, `ParsingJobFailureReason`) and new models (`OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, `RelatedCandidate`) to support expanded lab testing, order management, and timeseries query workflows. New provider entries (`SAMSUNG_HEALTH`, `TANDEM_SOURCE`) and lab entries (`SONORA_QUEST`, `CRL`) have been added to their respective enums, along with new order statuses (`CORRECTED`, `LAB_PROCESSING_BLOCKED`) and additional fields (`access_notes`, `order_transaction`) on address and lab result types.
* The SDK now includes several new types: `ResultMetadataGender`, `SearchMode`, `SearchCompendiumResponse`, `UsState`, and `UserAddress` to support compendium search and US address handling. The `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains the `RECOVERY_READINESS_SCORE` enum value.
