## 3.0.0 - 2026-04-02
* The `vital.link.types` submodule and its five public enum classes (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed — callers importing these types will need to remove those imports. The `INSULIN_INJECTION` member has been removed from `IntervalTimeseriesExprTimeseries`; code referencing this enum value or passing it to `.visit()` must be updated.
* Additionally, `AppointmentPscLabs` has been expanded from a `Literal["quest"]` type alias to a full `StrEnum` with `QUEST` and `SONORA_QUEST` values. The SDK now supports optional HTTP request/response logging (with automatic redaction of sensitive headers) via a new `logging_config` parameter on the HTTP client. `BaseHttpResponse` now exposes a `status_code` property.
* The `parser_create_job` method's `file` parameter has changed from `core.File` to `typing.List[core.File]`. Existing callers must wrap their single file argument in a list (e.g. `file=[my_file]`).
* Five previously exported `LinkBulk*RequestTeamId` symbols (`LinkBulkExportRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, `LinkListBulkOpsRequestTeamId`) have been removed from the public API.
* The SDK also adds three new submodules (`compendium`, `lab_account`, `order_transaction`) and many new types including `ClientFacingLabAccount`, `ClientFacingOrderTransaction`, `OrderSummary`, `OrderOrigin`, `SearchCompendiumResponse`, `UsState`, `UserAddress`, and more.
* The `get_psc_appointment_availability()` method now requires a `lab` parameter of type `AppointmentPscLabs` (e.g. `AppointmentPscLabs.QUEST`). Existing callers that omit this argument will receive a `TypeError` at runtime. Update all calls to pass the `lab` argument.
* In addition, several new optional parameters have been added across the lab tests client: `lab_slug` and `lab_account_id` on lab test creation and `get_markers()`; `order_transaction_id` on order listing; `appointment_notes` on phlebotomy appointment requests; `allow_stale`, `idempotency_key`, and `idempotency_error` on PSC appointment methods; and `clinical_notes` on `create_order()`. Two new types, `AppointmentPscLabs` and `Labs`, are now available.
* The SDK now supports several new optional parameters across lab test and order endpoints:
* `lab_account_id` and `lab_slug` on lab test creation for specifying the lab account and lab slug
* `lab_slug` on `get_markers` to filter markers by lab slug
* `order_transaction_id` on order listing for filtering by transaction ID
* `appointment_notes` on PSC appointment creation
* `allow_stale` and a now-required `lab` parameter (type `AppointmentPscLabs`) on `get_psc_appointment_availability` — note that `lab` was previously hardcoded to `"quest"`, so existing callers must now pass it explicitly
* `idempotency_key` and `idempotency_error` on PSC appointment booking (closed beta)
* `clinical_notes` on order creation
* Two new types are available: `AppointmentPscLabs` and `Labs`.
* The `team_id` parameter has been removed from `link.list_bulk_ops()`, `link.bulk_import()`, `link.bulk_trigger_historical_pull()`, `link.bulk_export()`, and `link.bulk_pause()`. The associated types `LinkListBulkOpsRequestTeamId`, `LinkBulkImportRequestTeamId`, `LinkBulkPauseRequestTeamId`, `LinkBulkTriggerHistoricalPullRequestTeamId`, and `LinkBulkExportRequestTeamId` have also been removed from `vital.link` — callers referencing these must remove them. Additionally, `link.connect_manual_provider()` now accepts new optional parameters `vital_ios_sdk_version`, `vital_android_sdk_version`, and `granted_permissions` for mobile SDK version tracking and permission reporting.
* Several breaking changes are included in this release alongside new features.
**Breaking changes:**
* The `address` parameter type in `UserClient.create_user()` (sync and async) has changed from `Address` to `UserAddress`. Callers must update their imports and usage: replace `from vital import Address` with `from vital import UserAddress`.
* `ParsingJob.job_id` field has been removed. Code accessing `job.job_id` will raise an `AttributeError`.
* `Jpeg.content` and `Png.content` have changed from `str` to `bytes`. Code that treats these fields as strings will break.
**New features:**
* New `client.compendium` sub-client with `search()` and `convert()` methods for lab test compendium operations.
* New `client.lab_account` and `client.order_transaction` sub-clients.
* New optional `logging` parameter on `Vital` and `AsyncVital` for configuring SDK-level logging.
* `ClientFacingInsulinInjectionSample` now includes optional `delivery_mode`, `delivery_form`, and `bolus_purpose` fields.
* `ClientFacingOrder` now includes optional `clinical_notes`, `last_event`, `origin`, and `order_transaction` fields.
* `ResultMetadata` previously-required fields are now optional; a new optional `gender` field has been added.
* The SDK now includes three new client namespaces: `lab_account` (for querying team lab accounts), `order_transaction` (for retrieving order transactions, results, and streaming PDF reports), and an expanded `compendium` raw client (with `search` and `convert` endpoints). A structured logging API (`ILogger`, `ConsoleLogger`, `LogConfig`, `Logger`, `create_logger`) is now available from `vital.core` for consumer-configurable log output.
* The SDK now includes a new `RawOrderTransactionClient` (and async variant) for retrieving order transactions and their results, including streaming PDF downloads. Approximately 40 new public types have been added to `vital.types`, including `ClientFacingOrderTransaction`, `ClientFacingLabAccount`, `GetOrderTransactionResponse`, `OrderTransactionStatus`, `SearchCompendiumResponse`, `ConvertCompendiumResponse`, and more. The `Address` type also gains a new optional `access_notes` field.
* The SDK now supports insulin injection timeseries data with new `ClientFacingInsulinInjectionSample*` enums and `InsulinInjectionTimeseriesExpr` model. New lab account management types (`ClientFacingLabAccount`, `GetTeamLabAccountsResponse`), order transaction models (`ClientFacingOrderTransaction`, `GetOrderTransactionResponse`), and lab report parsing job webhook events have been added. Sonora Quest is now available as a provider in `AppointmentProvider` and `ClientFacingLabs`, and several existing models have been extended with new optional fields including `recovery_readiness_score` on `ClientFacingSleep` and async confirmation options on `AppointmentBookingRequest`.
* The SDK now supports new lab testing and order management capabilities. New enums `LabAccountDelegatedFlow`, `LabAccountStatus`, `OrderOrigin`, `OrderStatusDetail`, `OrderTransactionStatus`, and `ParsingJobFailureReason` have been added. New models `OrderSummary`, `PerLabCandidate`, `ProviderIdConversionResponse`, and `RelatedCandidate` are now available. Existing enums (`Labs`, `Providers`, `ManualProviders`, `PasswordProviders`, `OrderStatus`, `OrderLowLevelStatus`, `PayorCodeExternalProvider`) have been extended with new values, and address models now include an optional `access_notes` field.
* The SDK introduces several new types to support lab compendium search and address management. New models include `SearchCompendiumResponse`, `SearchMode`, `UsState`, `UserAddress`, and `ResultMetadataGender`. The existing `UsAddress` model gains an optional `access_notes` field, and `SleepColumnExprSleep` gains the `RECOVERY_READINESS_SCORE` enum value.
